# Google Apps Script export prototype

A separate Apps Script web app that uses the **native Google Docs advanced service** (`Docs.Documents.create/get/batchUpdate`). It can be opened directly or embedded from MegaDoc to create a Google Doc or conservatively overwrite an eligible existing Doc. The code has local mock tests but has **not been deployed or tested against a real Google account/API**.

## Setup and deployment

1. At [script.google.com](https://script.google.com/), create a standalone Apps Script project. Paste `Code.gs` into `Code.gs` and create an HTML file named `Index` with the contents of `Index.html`.
2. Under Project Settings, show `appsscript.json` and replace its contents with this directory's manifest. It enables the Google Docs API v1 advanced service (`Docs`) and Google Drive API v3 advanced service (`Drive`). The Drive service is needed to list recent Docs. If you prefer the editor's Services menu, add Google Drive API v3 with identifier `Drive` as well as the existing `Docs` service, and still update the manifest scopes. With the default Apps Script Cloud project, enabling the advanced services normally enables their APIs automatically; a standard Cloud project requires enabling both APIs in Google Cloud. Save.
3. Deploy > Manage deployments > Edit (or New deployment > Web app). Choose **Execute as: User accessing the web app** and the narrowest appropriate access. Deploy a new version after updating the files/manifest. Open the `/exec` URL directly and reauthorize the new Google Drive scope when prompted. Google may show an unverified-app warning; organization policies may prevent authorization.
4. The official MegaDoc origin `https://chibbit-99.github.io` is allowed by default. If you previously set `MEGADOC_ALLOWED_ORIGINS` in **Project Settings → Script properties**, that property overrides the default; include the correct origin there. Custom-hosted MegaDoc installations must set it, e.g. `["https://your-host.example"]` or `["http://localhost:8000"]`. Use origins only, no path, trailing slash, or `*`.
5. Open MegaDoc as a top-level page. Choose **File → Export current tab to Google Docs**, paste the deployment's `/exec` URL (both standard `https://script.google.com/macros/s/.../exec` and Workspace `https://script.google.com/a/macros/your-domain/s/.../exec` forms are accepted), and select **Open exporter**. MegaDoc remembers the link in this browser's local storage; **Forget saved link** clears it. No HTML-service origin needs to be entered. If Google changes the iframe origin after redeployment or an account change, MegaDoc asks you to confirm the changed connection before sending. Alternatively set `appsScriptUrl` in the public root `google-docs.config.json` as a default; it is not secret storage.
6. Review the received content and conversion warnings, then choose Create. To replace an existing Doc, choose **Load recent Google Docs**, select a document (or paste a URL/ID), inspect it and type its exact title to confirm. This replaces existing text; it does not append. Make a backup first. The recent list queries the first 50 non-trashed Google Docs ordered by most recently viewed, and shows up to 20 editable ones; it may omit some documents. The direct web-app URL also allows manual paste. If transfer fails, use **Export current tab as text** and paste it into the directly opened app.

The app requests `https://www.googleapis.com/auth/documents`, which can access **all Google Docs available to the authorizing user**, and `https://www.googleapis.com/auth/drive.readonly`, which allows viewing and downloading **all Drive files available to that user**, not just the selected one. The Drive scope supports the recent-document list; Google may ask for consent again even if you authorized an earlier version. Inspect the code and only authorize a deployment you trust; do not execute a public deployment as the owner. You can revoke access in your Google Account security settings. Apps Script and Google's services process the exported content; this code intentionally does not log document content. No credentials or access tokens should be placed in source, URLs, or MegaDoc configuration.


## Format and limits

Plain text is split into paragraphs. A structured JSON input can specify headings and inline styles:

```json
{"version":1,"title":"Notes","blocks":[{"kind":"HEADING_1","runs":[{"text":"Heading"}]},{"kind":"NORMAL_TEXT","runs":[{"text":"Hello ","style":{"bold":true}},{"text":"world","style":{"link":"https://example.com"}}]}]}
```

MegaDoc converts the current editor DOM to structured paragraphs and runs. Supported features include headings; bold, italic, underline, strikethrough, superscript and subscript; font family and size; text and highlight colors; HTTP(S) links; paragraph alignment, first-line/left/right indentation and spacing (including supported line spacing); simple bulleted/numbered lists with nesting; and rectangular tables in new Docs, including rich cell paragraphs, cell fill, explicit pixel/point column widths and minimum row heights. Some editor defaults (line spacing, heading spacing, quotes, links and code) are approximated. The exporter translates those into Docs API insert, text-style, paragraph-style and list requests. Original HTML is not sent or executed. UTF-16 offsets are used, including for emoji; list requests are applied from the end because Docs removes leading tabs when creating bullets.

This is **not a lossless copy/paste**: images and media are omitted, equations become source text, footnote bodies, comments, history, page breaks, other tabs and internal links are not exported. Table borders, padding, percentage sizing, row heights without explicit units, surrounding blank lines and other layout may differ; merged, nested, uneven and oversized tables are rejected rather than flattened. Some list markers, start numbers, mixed nesting, line breaks, CSS and page layout may change. Unsupported content generates warnings where detected; check the resulting Google Doc and keep a MegaDoc JSON backup. No external images or resources are downloaded. Text/paragraph styles outside the mapped subset may still differ.

For manual JSON, each block is `NORMAL_TEXT` or `HEADING_1` through `HEADING_6`; optional `paragraph` fields are `alignment` (`START`, `CENTER`, `END`, `JUSTIFIED`) and `indentStart`, `indentFirstLine`, `indentEnd`, `spaceAbove`, `spaceBelow` in points and `lineSpacing` as a percentage. An optional `list` has `type` (`BULLET` or `NUMBER`) and `level` (0–8). Runs accept `bold`, `italic`, `underline`, `strikethrough`, HTTP(S) `link`, `fontFamily`, `fontSize` in points, `foregroundColor` and `backgroundColor` as `#rrggbb`, and `baselineOffset` (`SUPERSCRIPT` or `SUBSCRIPT`). Maximum 500 paragraphs, 1,000 runs and 100,000 UTF-16 units including breaks and list tabs. These are safety limits, not a guarantee of Google API capacity. For a table block, use `kind: "TABLE"`, `rows` as rectangular arrays of cells, `widths` as a per-column array of points or null, and optional `heights` as per-row minimum points or null; each cell has a nonempty `blocks` array of paragraphs and optional `backgroundColor` (`#rrggbb`). At most 10 tables, 20 rows or columns per table and 200 cells total are allowed; tables cannot be nested. Titles are 1–120 characters. Control characters, embedded newlines in runs and invalid surrogate pairs are rejected. Empty paragraphs have an empty `runs` array.

**Existing deployments must update and redeploy both `Code.gs` and `Index.html`** to accept the formatted payload. An older deployment rejects the new payload and may cause the transfer to time out.

## Overwrite safety and limitations

**Table-containing exports can only create a new Doc**, not overwrite an existing one. Docs requires table insertion and cell population in separate updates, which would make a destructive overwrite non-atomic. New-Doc table exports use staged revision-locked updates and read back actual cell indices; any failure links the potentially incomplete new Doc, which should be checked before retrying.

Overwrite first reads the complete tab tree with inline suggestions and included comments, and rejects multi-tab documents, comments, suggestions, named ranges, headers, footers, footnotes, inline/positioned objects, lists and non-text body structures. Unsupported or inaccessible inspection fails closed. The Docs API's comment-inclusion support may require enrollment in Google's Workspace Developer Preview or may not yet be available to the Apps Script advanced service; if so, **overwrite will refuse to proceed**, not fall back to an unsafe inspection. Creating a new Doc does not depend on this feature.

A user-scoped, five-minute, one-use confirmation binds the target revision and content. On confirmation the app re-inspects the document, then sends deletion, insertion and styling in a single batch with `requiredRevisionId`; concurrent changes cause failure. A timeout or other API error can leave the result unknown, so inspect the document before retrying. Creating a document and filling it requires multiple calls; if the second fails, the app links the possibly empty/partially updated document. Google Docs version history may allow recovery, but is not a substitute for a backup. This is a prototype, not a guarantee against all Google Docs features or API behavior changes; the overwrite path needs real-account verification before production use.

## Iframe, privacy and security limitations

MegaDoc loads the `/exec` URL with only a random request identifier and waits for a ready message from the nested HTML-service iframe. It checks the Google HTML-service origin pattern, verifies the sender is a descendant of the exporter iframe, and sends the tab only to that frame and its exact origin. On first use the observed origin is **automatically trusted** for the deployment URL entered by the user and saved locally after acknowledgement. If it changes, a user must approve the changed connection before sending again. The Apps Script page accepts messages only from the top-level window at an allowed MegaDoc origin and with the same request identifier. No Docs write happens until the user chooses an action. The ID correlates messages; **it does not authenticate a deployment**.

This automatic first-use origin discovery is a usability trade-off: a Google-owned origin, matching request ID and descendant frame do not independently prove which Apps Script deployment is running. A compromised deployment, Google-hosted frame, or MegaDoc host may receive the tab. Only use a deployment and MegaDoc host you trust; do not use this prototype for sensitive documents without reviewing and testing it. The link and discovered origin are saved in browser local storage, not document text or tokens. Document text and supported formatting are not put in the URL but are sent to Google when exporting. Unexpected origin changes require explicit confirmation; changed frame structure, an opaque origin, sign-in, third-party-cookie policies or an incorrect allowed-origin property can cause a timeout. MegaDoc must be top-level; if embedded, open it in a top-level tab.

Apps Script HTML Service uses an iframe sandbox with `allow-scripts` and `allow-same-origin` ([Google's restrictions](https://developers.google.com/apps-script/guides/html/restrictions)); nested HTML-service frames can communicate with a top-level embedding page using `postMessage` ([example discussion](https://stackoverflow.com/questions/56400233/navigating-embedded-google-apps-script-iframe-from-the-parent)). This implementation follows that approach, but the exact Google redirect/frame chain and origins have **not been tested on a real Apps Script deployment**. Chrome, Firefox, Safari, mobile and Google Workspace policies still need real-account testing.

The script enables `XFrameOptionsMode.ALLOWALL` so it can be framed. **Any site can frame the deployment**, and the message allowlist is not a complete clickjacking defense. The exporter’s buttons can be disguised by a malicious site even if that site cannot send it a tab. Restrict deployment access, open it directly if in doubt, and do not execute a public deployment as the owner. Sign-in and consent may require opening the deployment directly in a new tab. The direct fallback link contains no document text; paste a local text export there if the handshake fails. The root `GOOGLE_DOCS_EXPORT_PLAN.md` describes longer-term safeguards and conversion goals.

## Local checks

Run `node google-apps-script/tests/server.cjs
node google-apps-script/tests/tables.cjs` and `node --check < google-apps-script/Code.gs`. To test the integration UI, install `jsdom` outside the repository (for example `npm install --prefix /tmp/megadoc-test jsdom`) and run `NODE_PATH=/tmp/megadoc-test/node_modules node tests/google-docs.cjs`. These tests use mocks and jsdom; they do not verify authorization, real iframe redirects, deployment, Google API compatibility or actual rendered Docs.
