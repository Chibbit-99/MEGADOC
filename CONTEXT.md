# MegaDoc: context for future contributors

## Product intent

MegaDoc is a local-first, Docs-like editor for keeping notes in **one document** organized as tabs, subtabs, and deeper descendants. Each tab has its own editable page. New documents and new tab pages start empty; screenshot examples were illustrative and must not be reintroduced as starter content. Keep the familiar document-editor feel while maintaining MegaDoc's own identity: restrained, functional UI rather than a Google Docs clone or a generic promotional SaaS interface.

## Non-negotiable: cross-version data compatibility

**Saved data must always remain cross-compatible when the app is updated.** Treat an existing user's local document and exported backups as durable data, not disposable demo state. An update must not silently hide, reset, overwrite, or discard it. In particular:

- New releases must continue to open and preserve documents and exports created by all previous releases. Keep the tab tree and ordering, IDs and relationships, HTML content, comments, history, document metadata, and user settings intact.
- Maintain compatibility in the other direction for supported older releases as well: favor additive, optional fields with safe defaults, retain unknown fields, and keep existing field meanings and representations. If a new feature cannot be represented in an older format, provide a lossless, tested compatibility/export path rather than silently dropping content. Never overwrite data that the running version cannot safely understand.
- If a schema or storage key must change, implement and test explicit, non-destructive migrations and downgrade/round-trip paths. Read the old key before writing a new one, retain the original until migration is verified, and preserve a recoverable backup. Handle legacy, missing, future-version, malformed, and storage-failure cases explicitly; do not replace an unrecognized save with an empty document.
- Cover compatibility with representative fixtures from every released schema: load old local saves and JSON exports, edit and save, reload, and export/import again. Test nested tabs, formatting, tables, comments, history, settings, unknown fields, and an older supported reader. Verify that failure leaves the original data recoverable.
- Import, reset, and restore are potentially destructive. Warn before replacement, validate before committing a new state, and preserve a backup. Do not store credentials or real secrets in examples, fixtures, or seed data.

This is a requirement for future work, **not a claim that every safeguard is already implemented**. The current format has no explicit schema version, import validation is minimal, and cross-version round-trip tests and automatic migration are not yet in the repository. Address these gaps before relying on a breaking format change. In particular, `megadoc-v1` data is currently available only through the explicit restore command; do not silently switch storage keys and strand users' data.

## Current architecture

- `index.html`: static app shell, menus, toolbar, sidebar, editor, dialogs, and status bar. It loads `css/style.css` and `js/app.js` with cache-busting query strings; update those when deploying changed assets if needed.
- `css/style.css`: layout, responsive rules, print styling, page and interface themes, and accent variables. Mobile uses a collapsible tabs panel; toolbar menus use fixed positioning to avoid scroll-container clipping.
- `js/app.js`: vanilla JavaScript for the state store, tab tree, editor, formatting and Markdown shortcuts, menus, table actions, import/export, settings, and event wiring. Rich text is saved as HTML from a `contenteditable` element; editor commands use browser editing APIs, including `document.execCommand`. Test selection, caret, undo, and mobile input whenever these paths change.
- The ruler has one handle for each page margin. Its positions and tick marks are calculated from the rendered page and scroll viewport, including zoom and sidebar changes. `state.margins` stays in document-space pixels; narrow-screen padding is display-scaled without rewriting saved margins. The old separate first-line marker was removed; previously saved HTML `text-indent` must remain intact.
- Equations are stored in editable tab HTML as MathML and source text in a noneditable span. The local `vendor/katex/katex.min.js` renderer generates MathML; preserve source, MathML, undo, and older-reader round trips. Never load math rendering from a network service.
- Optional `state.pageSetup` stores paper and orientation without changing old documents. The editor stays continuous; the isolated print preview uses generated page rules and the current margins. Per-tab `printLayout` stores plain-text header/footer and page-number placement; preserve unknown fields. Settings undo/redo is session-only and separate from text history. Test zoom, print, mobile and older saves.
- Optional per-tab `pageView` is `pageless` or `pages`; absent/unknown values display page view without being rewritten. Pageless reflows text to the viewport even when saved or pasted whitespace formatting would otherwise prevent wrapping, without rewriting that formatting. Wide tables and embedded objects may still need horizontal scrolling. It hides the ruler and existing break markers, and prevents inserting new breaks; it does not alter saved content or page/print settings. Print preview still uses saved breaks and headers; export support varies by format. Duplication retains the setting; old readers can retain the optional field but will show page view. Test tab switching, JSON, zoom, mobile, image controls, printing and native undo.
- Tab emoji icons use an optional `tabEmoji` string on each tab; missing values show the original folder/document icon. Existing state and exports retain their representation, and recursive duplication copies icons. Older versions can retain this optional field when saving, but do not display or edit it.
- Capitalization and letter spacing clone and transform selected text across blocks and replace the page as a native undo step. A serialization check restores the original if browser insertion changes unrelated markup. Exercise links, tables, images, embedded content, undo/redo and older HTML.
- Footnote references store note text and IDs in ordinary anchor attributes. A sanitized copy in the isolated Paged.js preview generates page-bottom notes; browser-menu printing of the editor and HTML/text exports use end-of-tab notes. Do not serialize transient print content into tab HTML. Very long notes are rejected when their area exceeds a page, but complex pagination still requires inspection.
- The current-tab table of contents is an ordinary table marked `data-megadoc-toc`; its generated links carry heading IDs or snapshot text/index. Updating replaces its generated content and stale links are rejected; preserve markers and test table undo, reload, and print.
- Merged tables retain each original cell’s attributes and live content in ordered `data-megadoc-merge-cell` parts. Split only verified MegaDoc-created merges, never discard malformed/imported structures; preserve this metadata and test edits, undo, JSON, and reload.
- Explicit print breaks use ordinary `<hr data-megadoc-page-break>` markers. The editable surface remains continuous; View → Paginated preview generates a separate read-only snapshot for printing. Preserve break markers and test undo, printing and complicated content across updates.
- Bookmark anchors and internal links are ordinary HTML with tab/bookmark IDs in data attributes; preserve them on editing and JSON round trips. Heading links use existing IDs when available, otherwise a title snapshot and index; stale targets are rejected rather than navigating to the wrong heading. Cross-tab links are MegaDoc-specific, not standalone HTML links.
- Optional `state.paragraphStyles` supplies document-wide normal and heading defaults. Preserve unknown fields on updates and reset, validate values before generating CSS, and remember that style-setting undo/redo is separate from native text undo. Older versions preserve the field but do not display it.
- DOCX import runs a local Mammoth bundle, DOCX export uses docx, and ODT import/export uses odf-kit, all in disposable timeout-limited workers. Archive directory preflight limits sizes but does not make untrusted ZIP files safe. Imported HTML is sanitized into a new tab. Keep non-destructive behavior, local processing, licenses and limited-fidelity warnings; these formats are not full backups.
- `print-preview.html` and `js/print-preview.js` paginate a sanitized current-tab copy with locally bundled Paged.js. Print from that frame; direct PDF uses html2canvas/jsPDF, rasterizes up to 20 pages and may differ. Preserve the original editor and warn about fidelity, overflow, remote images, and oversized notes.
- HTML/text import creates a new root tab; export is current-tab only. HTML uses local DOMPurify plus a conservative import allowlist; JSON is the full backup, and HTML/text intentionally lose some structure. Never execute imported scripts or replace existing tabs.
- Native copy/cut provides HTML and plain text; rich paste uses local DOMPurify and the conservative import style/URL allowlist before a single native undoable insertion. Clipboard-only legacy font tags and selected CSS properties are supported; MegaDoc-specific IDs and metadata are not retained. Text-only paste follows the browser path. Async menu paste checks the tab, content and selection again before inserting. Keep the sanitizer, size limit, clipboard permission fallback, unknown-file safety, and test desktop/mobile, undo, hostile HTML and copying to other apps.
- Find/replace searches within blocks in the current tab, including across inline nodes; it never matches across paragraphs or cells. Regular expressions use JavaScript syntax and replacement strings are literal. Replace-all edits are individually undoable. The tab-tree outline also lists current-tab headings.
- Inline formatting button state follows the editor selection and native keyboard shortcuts. Clear formatting resets inline styling and links; caret-only clearing defers a temporary editing marker until typing and removes it before saving. Heading/quote Enter creates a normal paragraph; Shift+Enter remains a soft break. Check browser undo and selection behavior when changing these paths.
- Image crops store `data-megadoc-crop` and CSS object-view-box, keeping the original source and pre-crop proportions; browsers without support show the uncropped image. Rotation uses the CSS rotate property and may overlap neighboring content. Preserve these attributes and test crop/reset, image resize, undo, links, and older readers.
- Image selection controls sit outside `#page` and are never serialized. Resize previews are transient; each completed drag or keyboard adjustment replaces the image or its enclosing inline wrapper using the browser editing command for undo/redo, retaining existing attributes and storing standard inline styles. Paragraph alignment targets a selected image as well as selected text. Image descriptions and inline/wrap/break layouts use the same undoable wrapper-replacement approach. Deletion also uses the editor command for undo. Exercise older image HTML, links, tables, zoom, scrolling, narrow screens, selection changes, undo/redo and viewing mode when changing this code.
- `assets/megadoc.svg`: favicon. The header has an inline version of the mark so its fill can follow the selected accent; keep the two in sync if the logo changes.
- `fonts/`: locally served UI and icon fonts and their licenses. The app has no build step, server-side component, or online account system.

## Data and persistence today

- The active document is JSON in browser `localStorage` under `megadoc-v2`. Storage is scoped to the browser and origin. `seedState()` supplies a blank document and `normalizeState()` backfills some missing fields. Changes are debounced through `save()`; the editor content is copied from the page by `saveCurrentContent()`.
- The document includes `docTitle`, `activeTabId`, `roots`, a `tabs` map, `expanded`, `margins`, `zoom`, `people`, `profile`, and `pageTheme`. Tabs contain an ID, title, parent ID, ordered `children`, HTML `content`, `updatedAt`, `history`, and `comments`. The roots and child ID lists define the tree. History is limited to 25 snapshots per tab.
- Appearance and Markdown shortcut preferences are stored separately under `megadoc-appearance-v1`; they are not included in a document JSON export. The **File → Restore previous local document** command reads the older `megadoc-v1` key on the same origin and replaces the active document after confirmation.
- **File → Export as JSON** serializes the document state; **Import JSON** replaces the current document. The current import path performs only basic validation and inserts saved HTML into the editor. Treat untrusted imported content as a security risk and improve validation/sanitization carefully without losing legitimate formatting or breaking compatibility.
- There is no automatic cloud backup, sync, collaboration, or actual sharing. Browser storage can be cleared or become unavailable; users should export backups. Clipboard and fullscreen operations can be restricted by the browser.

## Running and checking changes

From the repository root:

```sh
python3 -m http.server 8000
# Open http://localhost:8000
node --check js/app.js
```

`tests/editor-regression.cjs`, `tests/image-editing.cjs`, `tests/local-features.cjs`, and `tests/table-organization.cjs` are optional Chromium smoke tests for tab creation and icons, formatting, headings, colors, and images; see README for their dependencies. `tests/document-roundtrip.cjs` also exercises a representative full JSON backup and preservation of unknown fields; this is not a comprehensive cross-version compatibility suite. There is no build system. For behavior changes, exercise the app in a real browser and check the console for errors. At minimum, check blank tab creation and deep nesting; editing, autosave and reload; tab duplication/deletion/reordering; JSON export/import; Markdown on and off; selection and toolbar formatting; right-click table edits, header restoration and undo; light/dark and accent persistence; print; and narrow-screen tabs and menus. For storage changes, follow the compatibility fixture checklist above.
